# Воспроизведение быстрого скрининга

Рабочий каталог — корень репозитория VoiceCapture. macOS Apple Silicon, Xcode с SwiftUI/Translation, Python 3.12. Все команды ниже предназначены для отдельного нового прогона; готовые результаты не перезаписывать.

## Окружение

Создать окружение внутри игнорируемого каталога сборок, затем установить [зафиксированные зависимости](requirements.lock.txt). Python 3.12.13, torch 2.14.1, transformers 4.56.2, protobuf 7.36.2 использованы в этом эксперименте. Установка не должна менять системный Python.

Для GGUF использована [официальная macOS arm64 сборка b11433](https://github.com/ggml-org/llama.cpp/releases/download/b11433/llama-b11433-bin-macos-arm64.tar.gz), runtime 0.6.0-dev, commit 50569eb87. SHA256 архива: 5e7b2383009facb31404f308cdb9edd1fb15131330801408fb582bd05e188f97.

Распаковать её в игнорируемый каталог dist/translation-screening/llama. Перед выполнением скачанного бинарника проверить источник и SHA256. Ожидаемый путь задаётся аргументом --server в [runner](run_screening.py:65).

## Веса

[Загрузчик](download_models.py) фиксирует репозитории и ревизии. Он скачивает только пять выбранных открытых моделей и не пытается обойти gated-доступ. Ознакомиться с условиями моделей до использования: особенно Яндекс и Tencent.

- Яндекс: официальный Q4_K_M.
- HY-MT1.5 1.8B: официальный Q4_K_M.
- OPUS/T5 Small: исходные опубликованные веса, инференс FP32.
- MADLAD: исходные Google FP32; старый GGUF эксперимент не использовать как успешный.

Не скачивать параллельно с измерением. Веса не коммитить. SHA256 каждого использованного файла автоматически записывается в метаданные результата.

## Запуск

Запускать [run_screening.py](run_screening.py) через Python созданного окружения, указывая:

- модель: yandex / hy / opus / t5 / madlad;
- движок: llama для Яндекса/HY, transformers для остальных;
- путь: конкретный GGUF или каталог скачанного checkpoint;
- output: новый путь JSONL в игнорируемом каталоге результатов;
- device: mps для PyTorch;
- repetitions: 3;
- свободный локальный порт: по умолчанию 18765.

Каждый вызов работает только с одной моделью и сам завершает свой server-процесс. При ошибке сохраняется частичный JSONL, а не фиктивный успешный результат. Существующий файл не перезаписывается.

Для Apple запустить [build.sh](apple/build.sh), затем открыть созданный AppleScreening.app с двумя аргументами: абсолютный путь [корпуса](corpus.json) и нового выходного JSONL. Используется именно [неизменённый сервис VoiceCapture](../../Sources/VoiceCapture/AppleTranslationService.swift), но отдельный bundle identifier. Приложение само закрывается по завершении. Нельзя измерять Apple одновременно с другим инференсом.

## Проверка измерений

Для каждой модели должно быть:

- 2 warmup-ответа;
- 60 примеров × 3 прохода = 180 измеряемых ответов;
- финальная запись summary;
- отсутствие пустых ответов/ошибок либо явная фиксация их в отчёте;
- контроль обрезаний и изменения ответа между повторами.

Полный путь source-text → output измеряется внутри runner. Задержка запуска процесса и времени чтения весов не смешивается с тёплым переводом. Отдельно смотреть короткие фразы, абзацы и первый проход. Подробные ограничения описаны в [LIMITATIONS.md](LIMITATIONS.md).

## Анонимная оценка

[prepare_review.py](prepare_review.py) создаёт 6 пакетов по 10 примеров и отдельный ключ соответствия букв моделям. Порядок перемешивается отдельно для каждого примера. Генерация пакетов требует завершённых прогонов. Ключ до завершения оценок не читать.

Для каждого примера оценить все варианты A–F по шкале 0–3 из [методики](RESEARCH.md). Сохранить словарь scores и пояснения notes ко всем ненулевым оценкам в шести пакетах оценок. Допустимые переформулировки не штрафовать просто за несовпадение с эталоном. Не менять корпус и промпты по обнаруженным ошибкам.

[summarize.py](summarize.py) сначала валидирует все 360 оценок и лишь затем читает ключ, объединяет модели, считает тайминги/метрики/парные результаты относительно Apple и экспортирует компактные данные. При повторном эксперименте не смешивать новый случайный ключ со старыми оценками.

## Что не воспроизводит этот скрининг

Это не оптимизация runtime, не тест аудиозаписи и не доказательство качества на произвольном русском тексте. ASR может добавить ошибки, которых нет в корпусе. При близком результате следующим практическим шагом будут реальные проблемные фразы пользователя, а не расширение числа моделей без необходимости.
